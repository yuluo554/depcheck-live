## 一、问题：四种"看起来都对"的状态，零个非零退出码

一个 AI 生成的调用点可以一路"看起来正常"而最终崩掉：

1. TypeScript 编译通过——但很多项目根本不上 `tsc`；
2. `import` / `require` 成功——Node 24 的 `require()` 对纯 ESM 包**不抛错**，
   而是返回整个命名空间对象；
3. 拿到一个 `object`——`typeof pkg === 'object'` 为真，于是"看起来正常"；
4. 真正调用时崩——崩的位置**离真因隔了一整个加载机制**。

第 2、3 步就是本工具的判定带。实测（本机 Node v24.15.0）：

```
$ node -e "const c=require('chalk'); console.log(typeof c, typeof c.red, typeof c.default)"
object undefined function
```

`chalk` v6 是纯 ESM，`require()` **不报 `ERR_REQUIRE_ESM`**，而是把模块对象交回来，
真正的 API 挂在 `.default` 下。于是 `chalk.red.bold('x')` 在 `.bold` 那一行抛 `TypeError`，
**而真因是"API 在 `.default` 下"**。这类静默错位 AI 自己 debug 不出来，CI 也不会报
——因为整条链上没有任何一步返回非零退出码。

**本工具判定的对象只有一句话**：

> 源码里每一个对已装依赖的引用点，在「这份 `node_modules`」下是否真的可解析；
> 不可解析时，是缺导出、加载方式错、子路径未导出，还是版本行为已变。

**不是**"这个包发布得规不规范"（那是包作者视角，`publint` / `arethetypeswrong` 的领域），
**不是**"哪些导入没被用到"（`knip` 的领域，方向相反），**不是**"这段代码有没有 bug"。

## 二、五个判定态：判据与边界

五判定态与枚举成员的唯一定义在 `src/contract.mjs`，与 `SKILL.md` 契约块双向断言
（`tests/contract.test.mjs`）。下面对每个态讲清**它凭什么成立**、**它不覆盖什么**。

### 2.1 `RESOLVED` —— 该符号在声明的入口下确实导出

判据是**符号级**的，不是"包能加载"级的：把入口文件的导出面静态读出来（含相对
re-export 递归），再看引用点取用的符号是否在集合里。

> **为什么必须递归**：`date-fns@4.4.0` 的入口是 245 行 `export * from "./x.js"`，
> `zod@4.6.7` 的 `index.cjs` 是 `__exportStar(require("./v4/…"), exports)`。
> 只看首层会读出**空导出集**，于是每个真实引用点都变 `MISSING-EXPORT`——系统性假阳性。
> 递归只沿**相对**路径走；外部 re-export（`export * from "pkg"`）记 `UNPARSEABLE`。

### 2.2 `MISSING-EXPORT` —— 入口存在，但没有这个导出

符号不在导出面上，且**导出面确实读出来了**。后者是硬前提：
读不出时记 `UNPARSEABLE` 进 `gaps`，**不判** `MISSING-EXPORT`（误报比漏报代价高，
`plan/06` R2）。

### 2.3 `ESM-CJS-MISMATCH` —— 招牌判据，**四条同时成立**

判定为 `ESM-CJS-MISMATCH` 当且仅当：

1. 该包 `type` 为 `"module"`（或入口文件为 `.mjs`）；**且**
2. 该包 `exports` 中**不存在**任何 `require` 条件分支（含嵌套条件内部）；**且**
3. 引用点为 `require(<pkg>)` 或等价 CJS 加载；**且**
4. 被访问的属性挂在模块命名空间上而非 `.default` 上。

全文口径见 `data/README.md` §5.2。**为什么不能只看 `type`**：

| 包 | `type: module` | `exports` 有 `require` 分支 | `require()` 拿到的符号 | 判定 |
|---|---|---|---|---|
| `zod@4.6.7` | ✅ | ✅ | 取得到 | `RESOLVED` |
| `date-fns@4.4.0` | ✅ | ✅ | 取得到 | `RESOLVED` |
| `glob@14.0.3` | ✅ | ✅ | 取得到 | `RESOLVED` |
| `chalk@6.0.1` | ✅ | ❌ | 具名符号在 `.default` 下 | **MISMATCH** |
| `commander@15.0.0` | ✅ | ❌ | **直接挂在命名空间上** | **`RESOLVED`** |

> **关键反例是 `commander`**：它与 `chalk` 同为"无 `require` 分支"，但**判定相反**。
> 判据落在第 4 条"被取用的符号能否从命名空间直达"，不是"有没有 require 分支"这一条。
> 只看第 2 条会把 `commander` 误判成 MISMATCH（系统性假阳性）。`bench` 的 C3 对照组
> 专为此设：同一行 `require()`，chalk 判红、commander 与 zod 判绿。

**判据的固有边界（必须如实说明）**：在**无 `require` 分支**的包上，CJS 视角取一个
不存在的符号，**必然先命中** `ESM-CJS-MISMATCH`（判定顺序使然，见 `data/README.md` §5.4.2）。
不执行被测代码时，"名字在 `.default` 下"与"名字压根不存在"**无法区分**。
这不是缺陷，是判据的边界——判成"格式失配"比判成"缺导出"更保守，且给出修复方向（改用 `import`）。
**本工具不宣称能在 CJS 视角区分两者。**

### 2.4 `NOT-EXPORTED-SUBPATH` —— 子路径被 `exports` 屏蔽

`exports` 未列该子路径，**或**该子路径被显式 `null` 屏蔽。两种都判这个态，不判"不存在"：
`null` 是**屏蔽语义**（`data/README.md` §5.4 第 2、10 条），与"没有这个键"是两回事。

### 2.5 `AMBIGUOUS` —— 动态形态，不可静态判定（**不代表代码有错**）

判定对象是**调用点**而非"能不能匹配到某个正则"：先定位 `require(` / `import(` 调用点，
再对参数**分类**——可确定的字面量进静态桶，其余（变量、拼接、插值模板、跨行未闭合）
进 `ambiguous` 桶。任何一种参数形态都只落进两个桶之一，**不存在被静默丢弃的第三种**。

> **为什么不用"静态正则 + 动态兜底正则"两条互补规则**：实测
> `require("chalk" + suffix)`、`require("./" + x)`、`import("chalk" + s)` 三条
> **同时落进两条正则的空隙**被静默丢弃——那正是"把解析不到当不存在"。

只有 `AMBIGUOUS` 时退出码是 `0`，但报告里**显式计数**（`data/README.md` §5.1 硬纪律）。

## 三、`drift`：判据是符号行为，单位是引用点

`drift` 回答"代码写的老 API 在**装的那个版本**上还在不在"。三条口径（全文 `data/README.md` §5.5）：

1. **只在有离线基线时判定。** 基线 = `data/fingerprints/<pkg>.json`，由
   `tools/gen-baselines.mjs` 从**真实历史版本 tarball** 生成（带 `provenance.sha512`，可独立复算）。
   没有基线 → `NO-BASELINE` 进 `gaps`，**不猜**。
2. **判据是符号行为，不是 semver 字符串。**
   判定式 = 该点引用的符号 ∈ 基线版本的导出面 **且** ∉ 已装版本的导出面。
   版本号跨了 major 但符号仍在 → `RESOLVED`。**不得**因为"版本号不匹配声明 range"就报漂移。
3. **判定单位是引用点，不是整包。** 禁止"这个包的 `exports` 变了就报漂移"。

两条实测反例说明第 3 条为什么必须有（2026-11-01，本机 Node v24.15.0）：

- `date-fns` 3.6.0 → 4.4.0：`.` 导出面 **251 个名字一个不少**，只新增 134 个子路径键。
  整份 `exports` 指纹必然不同 → **按包比指纹是系统性假阳性**。
- `zod` 4.6.7 移除了 `ZodSchema` / `ZodEffects` / `ZodBranded` 等 **31 个符号**，
  但同一包里 `z` / `ZodError` 仍在 → 按包比会把"用的是还在的符号"也判红。

逐点判才判得出 C6 的"1 红 1 绿"。独立复核用真实 `require`：
`'ZodSchema' in zod3 === true` / `'ZodSchema' in zod4 === false`。

> **载体是被实测推翻后改的，不是改真值凑实现**：M1 骨架把 C6 写成 date-fns 3.x→4.x
> "旧 API 已删"，M3 实测该包只加不减；改用 zod 3.25.76→4.6.7 作 DRIFT 正例，
> date-fns 留在"无基线"一侧。改的**是错的那份真值**，实现没动。

## 四、不判与算不了：`gaps` 这一层为什么必须存在

工具最危险的一种失败不是"判错"，是**把"算不了"写成"没问题"**。因此事实层算不出来时，
一律进 `gaps` 并落退出码 `3`（`data/README.md` §5.1），**不进** `findings`：

| gap 种类 | 触发 | 为什么不判 |
|---|---|---|
| `NO_PACKAGE_JSON` | `node_modules` 下缺该包或 `package.json` 不可解析 | 依赖面不存在，无判据可用 |
| `NO_NODE_MODULES` | 工程无 `node_modules` | 同上 |
| `UNPARSEABLE` | `exports` 形态无法按 Node 语义解析 | 解析不了 ≠ 有问题 |
| `EXPORTS_NOT_DECLARED` | 包未声明 `exports`，需回落 main/index | 首期不复刻整个文件系统解析，不猜 |
| `EXPORT_SURFACE_UNPARSEABLE` | 导出面读不出（重导出链、动态赋值） | 误报比漏报代价高 |
| `NO-BASELINE` | `drift` 无离线指纹 | 不猜（`data/README.md` §5.5 第 1 条） |
| `LARGE_FILE_DOWNGRADED` | 单文件超上限，降级为字符串兜底扫描 | 覆盖率折损必须**显式出现**，不得静默跳过 |
| `UNREADABLE_FILE` | 文件读不出 | 同上 |

**`NO-BASELINE` 的单独口径**（M3 裁定）：它**不算**"发现问题"（不进 `problems`），
但**落在退出码 `3`**——因为 `3` 的触发条件里就写着"基准缺失"。
用户显式跑了 `drift` 却因缺基线什么都没比成，回 `0` 等于把"这一层没跑"写成"跑了没问题"。

## 五、零依赖与"不执行被测代码"两个承诺的技术后果

### 5.1 零第三方依赖 → 手写词法抽取，而非 AST

`dependencies` 与 `devDependencies` 均为空（CI 有一条专门断言）。后果：

- 引用点抽取是**词法级**的，不是 AST 级。复杂 TS 语法上可能抽不完整的 specifier
  ——那种情况一律 `AMBIGUOUS`（宁可多判不可漏判，`plan/06` R1）；
- 导出面读取也是**文本级**的（`export` / `exports.x =` / `__exportStar` / `Object.keys` 转发）。
  读不出时记 `UNPARSEABLE`，**不猜**（`plan/06` R2）；
- 测试用 `node:test`，无需任何包。跨版本行为靠 CI 的 node 20/22/24 矩阵证明。

### 5.2 不执行被测代码 → 一切结论都是静态推断

不 `require`、不跑被测工程、不联网。后果与边界：

- **`ESM-CJS-MISMATCH` 的第 4 条判据只能静态读导出面**——这正是 §2.3 那条固有边界的来源；
- 动态形态（运行时算出的包名）不可判定，记 `AMBIGUOUS`；
- 没有离线指纹就不猜版本漂移（`NO-BASELINE`）。

### 5.3 确定性

同输入两次 `--json` **逐字节一致**（`tests/cli.test.mjs` 钉住）。前提是：
判定路径零时钟、零随机（`tests/architecture.test.mjs` 扫源码断言），
findings / gaps 稳定排序（`file → line → status`）。

## 六、为什么"退出码"是可信度的落点

`data/README.md` §5.1 定义的码表里，**`0` 与 `3` 必须分开**：

- `0` = 跑了，确实没问题；
- `3` = **没跑成**（依赖缺失 / `node_modules` 不存在 / `package.json` 不可解析 / 基准缺失）；
- `1` = 跑了，发现问题；
- `4` = 用法错误；
- `2` **保留不用**（与 `1` 合并，避免与 shell 常见约定冲突）。

把"零命中"与"算不了"压成同一个码，工具就失去了全部可信度——因为你无法区分
"这个工程是干净的"和"这个工程我压根没看成"。

这条纪律由 `selftest` 现场造最小工程逐条诱发四个码来钉住（覆盖 `0`/`1`/`3`/`4`，
其中 `3` 有两个独立触发源：依赖缺失、基准缺失；`2` 保留不用由一条断言钉住）。
`selftest` 不读本仓路径、不联网，只在本机临时目录里造工程。

## 七、基准：逐条级与计数级是两件事

`bench` 面对的是**真实 `node_modules`**，不是 mock。它输出**两种粒度**，
量的是不同的东西，**不可混读**：

- **逐条级**：每个引用点的判定结果与语料真值逐条比对——"判得对不对"的直接证据；
- **计数级**：每份语料的退出码、`summary`、`byStatus`、负向断言逐项比对
  ——"整份语料是否可信"的证据。

> 前者不蕴含后者（全扫到 ≠ 每份语料自洽），后者也不蕴含前者
> （语料级断言可以过而某条引用点判错）。

具体数值（语料数、引用点数、断言数）随语料增补而变，**不在本文复制**：
见 `README.md` 的「基准指标」两节（实测数字）与 `data/README.md` §5（口径定义）。

**真值纪律**（M3/M4 两次假门修复后立的三条，`plan/04` §3）：

1. **真值字段必须有人读**——`expect` 里每个字段要么被 `bench` 断言，要么在
   `verifiedElsewhere` 里指名谁验（K33）。M4 发现 `bench` **从不读** `expect` 的
   `exitCode` / `summary` / `byStatus`，改实现后它们可以悄悄失配而全绿。
2. **调用形态由真值声明**（`expect.invocation`），`bench` 不猜（K34）。M4 发现 `bench`
   对所有 case 无条件传 `--with-drift`，于是 C1–C3 的 `expect.summary.gaps=0` 与真值
   调用形态**不同源**。
3. **负向真值用 `negativePoints`，不许写 `status`**（K35）。`OUT-OF-SCOPE` /
   `NOT-A-REFERENCE` **不是**五判定态成员，写成 `points[].status` 永远进不了 `findings`，
   按 status 对账必然失配。

## 八、契约块：`SKILL.md` ↔ `src/contract.mjs` 双向断言

第二交付形态（Agent Skill）的主入口是 `SKILL.md` 的契约块。它与 `src/contract.mjs`
**双向**一致，由 `tests/contract.test.mjs` 逐方向断言：

- **方向①** `contract.mjs` → `SKILL.md`：`STATUS` / `EXIT` / `KIND` / `SOURCE_EXTENSIONS` /
  `COMMANDS` / `TOOL` 的每个值都出现在契约块里；
- **方向②** `SKILL.md` → `contract.mjs`：契约块**按行归属**校验——每行的记号只能来自
  该行对应的枚举，**多一个少一个都红**。

> 只有方向①是假门的一半：它挡得住"代码加了值文档没写"，挡不住"文档写了代码里没有的值"。
> 方向②若写成"全局猜记号属于哪个枚举"，小写的 `COMMANDS` 与 `KIND` 会混在一起
> ——等于没验；所以判据是**按行**的。

另外三条纪律断言（都来自实测假门）：

- **负向值不得进枚举**：`OUT-OF-SCOPE` / `NOT-A-REFERENCE` / `ERROR` 不是契约块成员；
- **`2` 必须被声明为"保留不用"**（代码侧由 `tests/cli.test.mjs` 钉，文档侧由契约测试钉）；
- **数值口径不在 `SKILL.md` 复制**：阈值数字只许在 `data/README.md` §5.3 出现。

**这份测试本身也做过变异验证**（`node tools/verify-contract-mutations.mjs`，
11 组：1 组未改坏对照 + 10 组逐处改坏），全部 CAUGHT——即"改坏一处就红"。
一份全绿的契约测试与一份什么也不验的契约测试，输出完全一样；只有变异能区分。

## 十、复现

```bash
npm test                                  # 单元 / 契约测试（node --test，逐文件）
node tools/check-sprint-layout.mjs         # 布局门
node tools/check-desensitized.mjs          # 脱敏门
node tools/mutate-gates.mjs                # 两道门的变异验证
node tools/verify-contract-mutations.mjs   # 契约测试的变异验证

node bin/depcheck-live.mjs bench           # 基准（逐条级 + 计数级）
node bin/depcheck-live.mjs bench --clean   # 干净工程零误报
node bin/depcheck-live.mjs selftest        # 退出码语义自检
```

`bench` / `bench --clean` 与真实包实测需要五包在场：

```bash
npm i --no-save chalk@6 zod@4 date-fns@4 commander@15 glob@14
```

零依赖承诺不受影响（`--no-save`，`package.json` 的 `dependencies` 仍为空）。
