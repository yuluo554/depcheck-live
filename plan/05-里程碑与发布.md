> **演示录制的两条环境坑**（复现 demo GIF 时会踩，见 `HANDOFF-M6` §五）：
> ① Python 把输出重定向到文件时用 locale 编码（本机 cp936），中文会被编成 GBK 字节 →
> 整屏 `U+FFFD`。正解：写 `sys.stdout.buffer` 的 UTF-8 字节。
> ② Git Bash 的 `/etc/bash.bashrc` 会给提示符塞进 `user@HOST` 与 git 分支，
> `--norc` / `--rcfile` **都挡不住**。正解：先发一条初始化命令清 PS1 并 `clear`，
> **然后才开始收集字节**（被丢弃的只是 shell 启动横幅）。

> **M5 修的一处变异宿主缺陷（`tools/mutate-gates.mjs` 的 H2 组）**：
> H2 的靶子原写成"当前里程碑之后的那个 ⬜"（要求 `pending.length >= 2`），
> **那是锚进度状态**——M5 收尾后只剩 M6 一个 ⬜，该组直接 SKIP，宿主报"1 组不符预期"。
> 而宿主文件头部纪律明写"变异靶子一律锚**既有事实**，永不随进度过期"，这条靶子违反了它。
> 修法：门的半边②本来就有**两条独立判据**，改用不随进度变化的那条（**野编号**
> `HANDOFF-M<k>.md` 里 k 不在里程碑表 → 也是超前入口）作兜底靶子；
> 有 ⬜ ≥ 2 时仍优先用表内判据（更贴近真实误用场景）。修后 **20/20 CAUGHT**。

   （**`-X GET` 不能省**；0 必须来自成功响应，不是限流假 0），并把"核过、未占用、无映射"写进留档。

6. tag 后在 `git archive <tag>` 解出树里重跑三道门。
