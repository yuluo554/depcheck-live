# 02 · 架构与技术选型 — 11-1-depcheck-live

> 本文只写**分层与选型理由**。一切可漂移的数值（容差、退出码、判据阈值）**只在 `data/README.md` §5 定义一次**，本文只引用编号。

## 1. 定位与架构约束

工具的判定对象是一句话：**源码里每一个对已装依赖的引用点，在「这份 `node_modules`」下是否真的可解析。**

由此推出三条架构硬约束（选型全部服从它们）：

| 约束 | 含义 | 对架构的后果 |
|---|---|---|
| **C1 零执行** | 不 `require`、不 `import()`、不运行被测工程任何代码 | 判定层必须是**纯静态**；所有"实测交叉验证"只允许出现在**测试**里（对固定的五个公开包） |
| **C2 零联网** | 不查 registry、不下载包 | 判据只来自本地磁盘；`drift` 的历史指纹必须由用户显式提供离线包 |
| **C3 零第三方依赖** | 不安装任何 npm 包 | AST 抽取要自己写（词法级 + 显式 `AMBIGUOUS`）；测试用 `node:test`；文件 IO 用 `node:fs` |

## 2. 构建（技术选型）

| 维度 | 选型 | 理由 |
|---|---|---|
| 运行时 | **Node ≥ 20**（本机实测 v24.15.0） | `node --test`、`node:` 前缀、ESM 均稳定；`exports` 语义即被测对象的语义 |
| 模块形态 | **ESM**（`"type": "module"`） | 与"判据面同构"一致；同时**避免**自身踩 `require(ESM)` 坑 |
| 依赖 | **零**（`dependencies` / `devDependencies` 均为空） | C3；且"无第三方依赖"要落成 CI 断言而非 README 措辞 |
| 测试 | `node --test`，**逐文件列出** | `node --test <目录>` 在部分版本行为不同；逐文件列出 + 两处登记对账（布局门 `LAYOUT.TESTS`） |
| CLI 解析 | 手写（`src/cli.mjs`） | `node:util` 的 `parseArgs` 在 20 上行为与 22/24 有差异；手写 30 行即可，且退出码完全可控 |
| 输出 | 人读（默认）+ `--json` | 一命令双轨；机读是契约面，人读是演示面 |
| 分发 | `bin` 字段 + Release zip | 无需 npm publish；安装面 = `npm link` 或 zip 解包 |
| 门 | `tools/*.mjs`，零依赖 | 与主代码同栈，CI 里一条 `node` 即可 |

**为什么不引入 AST 解析器**：`acorn`/`typescript`/`@babel/parser` 任一引入即破坏 C3，且**被测项目不一定装了它们**（工具不能在别人的仓库里要求安装自己的依赖）。首期用手写词法级抽取：能可靠覆盖 `import/export from/require()/import()` 的**静态字面量形态**，动态形态一律落 `AMBIGUOUS`——这正好是 `data/README.md` §5 要求的"严禁把解析不到当不存在"。

## 3. 分层

```
┌──────────────────────────────────────────────┐
│ 表现层   bin/depcheck-live.mjs → src/cli.mjs │  参数面 / 退出码 / 人读+json
├──────────────────────────────────────────────┤
│ 编排层   src/api.mjs  run()                  │  纯函数：(opts, io) → result
├──────────────────────────────────────────────┤
│ 判定层   src/check.mjs   checkAll()          │  五判定态 + NO-BASELINE
│          src/drift.mjs   driftAll()          │  版本行为漂移
├──────────────────────────────────────────────┤
│ 解析层   src/resolve.mjs resolveExports()    │  Node `exports` 语义
│          src/scan.mjs    scanSources()       │  引用点抽取（含 AMBIGUOUS）
├──────────────────────────────────────────────┤
│ 事实层   src/snapshot.mjs readProject()      │  只读 package.json / node_modules
├──────────────────────────────────────────────┤
│ 常量层   src/contract.mjs                    │  判定态枚举 / 退出码 / 契约块的唯一来源
└──────────────────────────────────────────────┘
```

**依赖方向严格单向向下**（表现 → 编排 → 判定 → 解析 → 事实 → 常量）。
`contract.mjs` **不得** import 任何其它 `src/` 模块——它是 `SKILL.md` 契约块的对账方，必须能被单独加载。

| 层 | 允许做的事 | 禁止做的事 |
|---|---|---|
| 事实层 | 读文件、解析 JSON | 读源码语义、判断对错 |
| 解析层 | 把 `exports` 字段与源码文本转成结构 | 决定"这份调用对不对" |
| 判定层 | 组合解析结果给出判定态 | 触碰 `process.exit`、写文件 |
| 编排层 | 组织成 result 对象 | 触碰 `process.exit`、写文件 |
| 表现层 | argv / stdout / 退出码 | 重新计算判定 |

**"判定与呈现分家"**：判定层与编排层是**纯函数**（输入 `{cwd, files, io}`，输出 `result`），退出码只在 `cli.mjs` 一处决定。这样同一份 `result` 同时服务 `--json`、人读摘要、`bench` 与 `selftest`。

## 4. 数据流

```
cwd
 └─ package.json ──→ snapshot.readProject()
      ├─ dependencies / devDependencies  ──→ 依赖面（声明 range → 实际安装 version）
      └─ node_modules/<pkg>/package.json ──→ exports 结构指纹 + type + 是否暴露 ./package.json
                                                │
源码树 → scan.scanSources() ──→ 引用点 {file,line,kind,specifier,imported}
                                                │
                                    check.checkAll() ──→ findings[] {status, evidence}
                                                │
                                          api.run() ──→ result {summary, findings, gaps}
                                                │
                       cli.mjs ──→ stdout（人读 / --json）+ 退出码（data/README §5.1）
```

## 5. 确定性保证（本项目的核心卖点之一）

| 保证 | 实现手段 | 断言在哪 |
|---|---|---|
| 同输入同输出 | 无时钟、无随机、无网络；所有集合遍历前排序 | `tests/determinism.test.mjs`（双跑逐字节） |
| 无路径泄露 | 输出中的路径一律相对化（`rel(cwd, abs)`），跨盘符 `ValueError` 等价处理 | `tests/paths.test.mjs` |
| 无静默跳过 | 解析不了的 `exports` 记 `UNPARSEABLE` 并进 `gaps[]`；动态引用记 `AMBIGUOUS` | `tests/resolve.test.mjs` |
| 零命中 vs 算不了 | 退出码 0 vs 3（`data/README.md` §5.1） | `tests/cli.test.mjs` |

## 7. 构建与运行

```bash
node bin/depcheck-live.mjs --version          # 版本（读 package.json，单一来源）
node bin/depcheck-live.mjs check .            # 主命令
node bin/depcheck-live.mjs check . --json     # 机读
node bin/depcheck-live.mjs selftest           # M4 落位
node bin/depcheck-live.mjs bench              # M3/M4 落位
npm test                                       # node --test，逐文件
node tools/check-sprint-layout.mjs            # 布局门
node tools/check-desensitized.mjs             # 脱敏门
node tools/mutate-gates.mjs                   # 两道门的变异验证
```
