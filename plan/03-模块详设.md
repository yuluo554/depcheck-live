## 2. 模块 ① 依赖面快照（`snapshot`）

**输入**：项目根目录（含 `package.json` / 锁文件 / `node_modules`）。
**输出**：每个直接依赖一条记录。

```js
{
  name: "chalk",
  declaredRange: "^6.0.1",        // package.json 里声明的 range（dependencies ∪ devDependencies）
  installedVersion: "6.0.1",      // node_modules/<pkg>/package.json 的 version；缺失 → null
  type: "module",                 // "module" | "commonjs" | null（未声明按 commonjs）
  exportsFingerprint: "…",        // 结构指纹：见 §2.2
  exposesPackageJson: false,      // exports 是否列了 "./package.json"
  parseState: "OK"                // "OK" | "UNPARSEABLE" | "NO_PACKAGE_JSON"
}
```

### 2.1 `exports` 六形态（判据来源 = `data/README.md` §5.4，**M1 已逐条核对 ✅**）

| # | 形态 | 例 | 解析要点 |
|---|---|---|---|
| 1 | `"."` 字符串 | `"exports": "./index.js"` | 等价于 `{".": "./index.js"}`（含条件对象 sugar） |
| 2 | 条件对象 | `{".": {"import": "./i.mjs", "require": "./i.cjs"}}` | 条件**按目标对象自身键序**匹配，取第一个命中的 |
| 3 | `null` 屏蔽 | `{"./secret": null}` | 命中即 `NOT-EXPORTED-SUBPATH`（**不是**"不存在"） |
| 4 | 数组回退 | `["./a.js", "./b.js"]` | 逐项求值，`invalid`/`unmatched`/`null` 一律**继续**；空数组 = 屏蔽 |
| 5 | 通配 `*` | `"./features/*": "./src/features/*.js"` | 单 `*` 替换；**优先级 = `PATTERN_KEY_COMPARE`**（`*` 下标大者优先，同则整键长者优先） |
| 6 | 嵌套条件 | `{".": {"node": {"import": "./n.mjs"}, "default": "./d.js"}}` | 递归下降；**无映射时继续父层后续条件**；`default` 是兜底 |

> **顺序**与**最具体优先**是两条独立规则，**不得合并实现**（错一处会让整族判定反转）。
>
> ⚠️ **M1 的 D1 核对查出 M0 骨架 10 处偏差并已修正**（条件按键序而非优先级数组、嵌套无映射继续、
> 通配须排除等于 base、数组遇 null 继续、键形态致命性分档、`exports:null` 等同未声明 等）。
> **完整 10 条 + 官方原文锚点 + 本机实测编号见 `data/README.md` §5.4**——本节不重复，
> 改判定前先读那一节。测试向量在 `tests/resolve.test.mjs`，每条都标注了对应实测用例。

### 2.2 结构指纹（确定性纪律）

指纹 = 对 `exports` 值做**规范化序列化**后取 `sha256` 前 12 位十六进制：

- 对象键**排序后**序列化（否则同内容不同书写会得到不同指纹）；
- 数组保序（数组语义上是有序的）；
- `null` 保留为 `null`（它是**屏蔽语义**，不能丢弃）。

判据 = **同一份 `package.json` 在任何机器上得到同一指纹**（`tools/gen-fingerprints.mjs --check` 断言）。

### 2.3 `UNPARSEABLE` 的纪律

解析不了的形态**记 `UNPARSEABLE` 并计入覆盖率缺口**（进 `result.gaps[]`），**不得静默跳过**。
缺口计入 `summary.gaps`，且**不进误报**（它不是"发现问题"，是"算不了"）。

## 3. 模块 ② 引用点抽取（`scan`）

**输出**每个引用点：

```js
{ file: "src/a.mjs", line: 12, kind: "import", specifier: "chalk", imported: ["default"] }
```

| `kind` | 形态 | 抽取方式 |
|---|---|---|
| `import` | `import x from "p"` / `import {a} from "p"` / `import "p"` | 静态字面量 |
| `export-from` | `export {x} from "p"` / `export * from "p"` | 静态字面量 |
| `require` | `require("p")` / `const {a} = require("p")` | 静态字面量 |
| `dynamic-import` | `import("p")` | 静态字面量 |
| `jest-mock` | `jest.mock("p")` / `vi.mock("p")` | 静态字面量 |
| `string-literal` | Vue 模板 / 配置对象 / `data-*` 里的 `"lucide:xxx"` 式引用 | 兜底扫描 |
| `AMBIGUOUS` | 变量拼接、`require(v)`、运行时生成 | **显式落 `AMBIGUOUS`** |

**判据纪律**：
1. **严禁把"解析不到"当"不存在"**——抽不出 specifier 一律 `AMBIGUOUS`，写进 `findings`；
2. 字符串兜底**不误报**：只在"形似包名 + 已装依赖前缀"时计入（判定见 `data/README.md` §5.3）；
   **M1 已实现为 `findBarePackageLiterals()` 的"双条件同时成立"**，并且**必须去重**——
   `require("chalk")` 里的 `"chalk"` 也形似包名，但它已被 `require` 结构化抽取覆盖，
   再计一次就是同一引用点算两遍（M1 实测踩过，见 `tests/thresholds.test.mjs`）；
3. `line` 必须是**源行号**（宽字符、CRLF、超长行都要正确；`tests/scan-edge.test.mjs` 钉住）；
4. 只扫 `data/README.md` §5 声明的扩展名（`.js/.cjs/.mjs/.ts/.tsx/.vue`），默认跳过 `node_modules` 与 `.git`；
5. **单文件上限**（`data/README.md` §5.3，512 KiB）：超限降级为字符串兜底扫描并记
   `gaps[].kind = "LARGE_FILE_DOWNGRADED"`，**不得静默跳过**。

### 3.1 ✅ M2 实现口径：**调用点 + 参数分类**（取代"四条互补正则"）

M0 骨架用四条互补正则（静态 `require("x")` / 动态 `require(v)` / 静态 `import("x")` / 动态 `import(v)`）。
M2 实测发现**这四条合起来并不构成全覆盖**，整族形态被静默丢弃：

| 形态 | 四条互补正则的结果（M2 实测） | 正确结果 |
|---|---|---|
| `require("chalk" + suffix)` | 全不匹配 → **丢失** | `AMBIGUOUS` |
| `require("./" + x)` | 全不匹配 → **丢失** | `AMBIGUOUS` |
| `import("chalk" + s)` | 全不匹配 → **丢失** | `AMBIGUOUS` |
| `` require(`chalk`) `` | 落进"动态"分支 → **误判 AMBIGUOUS** | `require`（无插值模板串是静态的） |

现实现：先定位 **`require(` / `import(` 调用点**（`CALL_SITE`），再用 `readCallArgument` 做括号配平切出实参，
最后对实参**分类**——命中 `STATIC_ARG`（纯单/双引号字面量，或**不含插值**的模板串）→ 静态；
其余一切（变量、二元表达式、含插值模板、属性访问）→ `AMBIGUOUS`。
分类法只有两个桶，因此**任意参数形态都不会被丢弃**。

另修一处：解构 `require` 的 `imported` 曾**恒为空**——`REQUIRE_DESTRUCTURED` 从 `const` 起匹配，
而调用点下标从 `require` 起算，两者相差 `"const {…} = "` 那一段，早期版本拿前者当键。
后果是判定层把 `const {red} = require("chalk")` 读成"只加载包、不取符号"，C2/C3 的红条目全判绿。
现统一以**调用点自身的下标**为键。

### 3.2 ✅ M2 实现口径：字符串兜底的两条**让出**规则

兜底（`findBarePackageLiterals`）不得与调用点扫描器重复计数。除了 §5.3 的双条件与 `file+line+specifier` 去重，
M2 又补两条**让出**规则：

1. **落在 `require(…)` / `import(…)` 参数区里的字面量让给调用点**——
   否则 `require("chalk" + suffix)` 的 `"chalk"` 前缀会被兜底计成 `RESOLVED`，
   同一行同时出现 `RESOLVED` 与 `AMBIGUOUS`（等于对用户说"没问题"又说"判不了"）。
2. **被当作动态 specifier 用过的标识符，其声明右值让给调用点**——
   否则 `const name = "chalk"; require(name)` 会产出两条结论；
   判据是"该标识符出现在某个非静态实参里"（含模板插值，如 `` `chalk/${x}` `` 里的 `x`）。

> 两条都是"同一引用点只许一条结论"的直接推论。兜底的正当用途仍然是 §3 表格最后一行的
> **`string-literal`**：Vue 模板 / 配置对象 / `data-*` 里的包名式引用。

## 4. 模块 ③ 解析判定（`check`）—— 招牌

### 4.1 五判定态（冻结于 `src/contract.mjs`）

| 判定态 | 含义 | 判据来源 |
|---|---|---|
| `RESOLVED` | 该符号在声明的入口下确实导出 | `exports` 解析后的目标文件 + 导出集 |
| `MISSING-EXPORT` | 入口存在，但**没有这个导出** | 同上 |
| `ESM-CJS-MISMATCH` | 入口只能 ESM 加载，`require()` 拿到命名空间对象，API 在 `.default` 下 | `exports` **无 `require` 分支** |
| `NOT-EXPORTED-SUBPATH` | 子路径被 `exports` 屏蔽 | `exports` 未列该子路径（或列为 `null`） |
| `AMBIGUOUS` | 动态形态，不可静态判定 | 见 §3 |

外加一个**非判定态**：`NO-BASELINE`（仅 `drift` 用，表示"没有离线指纹，不猜"）。

### 4.2 `ESM-CJS-MISMATCH` 的精确判据（本项目技术创新点）

当且**仅当**四条同时成立：

1. 该包 `package.json` 的 `type` 为 `"module"`（或入口文件为 `.mjs`）；**且**
2. 该包 `exports` 中**不存在**任何 `require` 条件分支（含嵌套条件内部）；**且**
3. 引用点为 `require(<pkg>)` 或等价 CJS 加载；**且**
4. 被访问的属性挂在模块命名空间上而非 `.default` 上。

**反面判据（必须判 `RESOLVED`）**：`type: module` **但有** `require` 分支 → **不得**判 MISMATCH。

> 这条是"看 `exports` 而不是看 `type`"的具体落地。`type` 单独不足以判定——`zod` / `date-fns` / `glob`
> 都是 `type: module` 却**有** `require` 分支。判据原文见 `data/README.md` §5.2。
>
> ⚠️ **M1 实测补充（关键，见 `data/README.md` §5.4.1）**：第 4 条不是"有没有 `require` 分支"的
> 复述，它要求同时看**被取用的符号在哪一层**。`chalk` 与 `commander` **同为**无 `require` 分支，
> 但 `require("chalk").red === undefined`（在 `.default` 下）而 `require("commander").Command === function`
> （在命名空间上）→ 判定相反。**只看第 2 条会把 `commander` 误判成 MISMATCH（系统性假阳性）**。
> M0 曾把两者并列成同类；M1 已纠正，C3 语料用"1 红 4 绿"形状钉住这一点。

### 4.3 导出集解析（`RESOLVED` vs `MISSING-EXPORT`）

"导出集"从**入口目标文件**静态读：

- `.cjs` / `.js`(CJS) → `module.exports` / `exports.x` 赋值形；`Object.defineProperty(exports, "x", …)`；
- `.mjs` / `.js`(ESM) → `export {a, b}` / `export default` / `export const a` / `export * from "…"`（外部 re-export 记 `UNPARSEABLE`）；
- **判定不了的形态**（`module.exports = someFunction()` 之类）→ 该包记 `UNPARSEABLE`，引用点记 `AMBIGUOUS`（**不猜**）。

#### 4.3.1 ✅ M2 实测：三条必须做的读取规则

只看首层 + 只看包根 `type` 的实现，在**真实五包**上会读出空导出集（实测每个包都是 0 个），
于是全部引用点退化成 `MISSING-EXPORT`——系统性假阳性。三条修法：

**① 模块类型按「最近的 `package.json`」判，不是包根。**
`glob@14.0.3` 的 `dist/commonjs/package.json` 写着 `{ "type": "commonjs" }`，而包根是 `type: module`。
按包根判会把这份 CJS 产物当 ESM 解析 → 导出集为空。判据 = Node 的 Module Type 判定：
从目标文件所在目录逐级向上找 `package.json` 的 `type`（`.cjs` 恒 CJS、`.mjs` 恒 ESM），找不到才回落到包根。
入口：`src/check.mjs` 的 `isEsmFile()`。

**② 相对 re-export 必须递归。**
- `date-fns@4.4.0` 的 ESM 入口 `index.js` 是 **245 行** `export * from "./x.js";`；
- `zod@4.6.7` 的 `index.cjs` 是 `__exportStar(require("./v4/classic/external.cjs"), exports)`；
- `date-fns@4.4.0` 的 CJS 入口是 **245 组** `var _indexN = require("./x.cjs"); Object.keys(_indexN).forEach(…)`。

三种桶形态都要沿**相对**路径展开。递归用 `seen` 集合去重，环与重复桶天然收敛
（实测触及文件数：date-fns 246 / zod 27 / glob 1 / chalk 2）。
**外部 re-export 仍记 `UNPARSEABLE`**——口径不变，只是把"相对"这一支补齐。

**③ 桶文件某支读不到 ≠ 整包算不了。**
首层读不出 → `ok:false`（真算不了）；深层某支读不出 → 跳过该支继续，
最终若**一个名字都没读到**且确有外部 re-export 才回落 `ok:false`。

> 容差：本层**不引入新阈值**。递归收敛靠 `seen` 去重，不靠数量上限——
> 添加新阈值就必须同轮改 `data/README.md` §5.3（数值唯一定义），成本与收益不成比例。

### 4.4 判定顺序（写死并测）

逐引用点按序求值，**首个成立者胜**：

```
AMBIGUOUS（specifier 抽不出）
  → NOT-EXPORTED-SUBPATH（子路径不在 exports）
  → ESM-CJS-MISMATCH（§4.2 四条）
  → UNPARSEABLE（导出集读不出，进 gaps）
  → MISSING-EXPORT（符号不在导出集）
  → RESOLVED
```

顺序本身要有测试（同一个输入只许出一条判定态）。
