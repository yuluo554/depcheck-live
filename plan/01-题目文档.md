## 一、介绍：能编译不等于能跑

一个 AI 生成的调用点，可以有四种"看起来都对"的状态：

1. **TypeScript 编译通过**——但很多项目根本不上 `tsc`（纯 JS、Vue 模板、配置对象、`require` 字符串）；
2. **`import` / `require` 成功**——Node 24 的 `require()` 对纯 ESM 包**不抛错**，而是返回整个命名空间对象；
3. **拿到一个 object**——`typeof pkg === 'object'` 为真，于是"看起来正常"；
4. **真正调用时崩**——崩的位置**离真因隔了一整个加载机制**。

第 2、3 步就是本案的判定带。实测（本机 Node v24.15.0，2026-11-01）：

```
$ node -e "const c=require('chalk'); console.log(typeof c, typeof c.red, typeof c.default)"
object undefined function
```

`chalk` v6 是纯 ESM。`require()` **不报 `ERR_REQUIRE_ESM`**，而是把整个模块对象交回来，
真正的 API 挂在 `.default` 下。于是：

```
$ node -e "const chalk=require('chalk'); chalk.red.bold('x')"
TypeError: Cannot read properties of undefined (reading 'bold')
    at Object.<anonymous> (...:8:23)
```

**报错在 `.bold` 那一行，真因是"API 在 `.default` 下"。** 这类"静默错位"AI 自己 debug 不出来，
CI 也不会报——因为整条链上**没有任何一步返回非零退出码**。

本项目的判定对象只有一句话：

> **源码里每一个对已装依赖的引用点，在「这份 `node_modules`」下是否真的可解析；
> 不可解析时，是缺导出、加载方式错、子路径未导出，还是版本行为已变。**

不是"这个包发布得规不规范"（`publint` / `arethetypeswrong` 已占），
不是"哪些导入没被用到"（`knip` 12560★ 已占，方向相反），
不是"这段代码有没有 bug"（见 §六 非目标）。

## 二、任务要求（模块化）

> **首期范围**：五个模块，全部锁死 **Node/TS 生态**（`package.json` + `node_modules` + `.js/.cjs/.mjs/.ts/.tsx/.vue`）。
> **不承诺** Python / PHP / Go / Rust 生态（见 §六）。

### 模块 ① 依赖面快照（`snapshot`）

- **输入**：项目根目录（含 `package.json` / 锁文件 / `node_modules`）；
- **输出**：每个直接依赖的「声明 range / 实际安装版本 / `type` / `exports` 结构指纹 / 是否暴露 `./package.json`」；
- **引擎**：只读 `node_modules/<pkg>/package.json`，**不 require、不执行**被测代码；
- **确定性纪律**：`exports` 字段一律按 **Node 官方 resolve 语义**解析（含 `"."` 字符串形式、
  条件对象、`null` 屏蔽、通配 `*`）；解析不了记 `UNPARSEABLE` 并计入覆盖率缺口，**不得静默跳过**。

### 模块 ② 引用点抽取（`scan`）

- **输入**：源码树；
- **输出**：每个引用点 `{file, line, kind, specifier, imported}`；
- **引擎**：AST 优先（`import` / `export from` / `require()` / 动态 `import()` / `jest.mock`），
  字符串字面量为兜底（Vue 模板、配置对象、`data-*` 属性里的 `"lucide:xxx"` 式引用）；
- **确定性纪律**：**动态形态必须显式落 `AMBIGUOUS`**（变量拼接、`require(variable)`、
  运行时生成的 specifier）；**严禁把"解析不到"当"不存在"**。

### 模块 ③ 解析判定（`check`）—— 本题招牌

五个判定态，逐引用点给出：

| 判定态 | 含义 | 判据来源 |
|---|---|---|
| `RESOLVED` | 该符号在声明的入口下确实导出 | `exports` 解析后的目标文件 + 导出集 |
| `MISSING-EXPORT` | 入口存在，但**没有这个导出** | 同上 |
| `ESM-CJS-MISMATCH` | 入口只能 ESM 加载，`require()` 拿到的是**命名空间对象**，API 在 `.default` 下 | `exports` **无 `require` 分支** |
| `NOT-EXPORTED-SUBPATH` | 子路径（如 `<pkg>/package.json`）被 `exports` 屏蔽 | `exports` 未列该子路径 |
| `AMBIGUOUS` | 动态形态，不可静态判定 | 见模块 ② |

- **引擎**：纯静态，零模型，**不对被测工程执行任何代码**；
- **确定性纪律**：`ESM-CJS-MISMATCH` 的判据**必须精确到 `exports` 的 `require` 分支存在性**，
  **不得只看 `type: module`**——实测 `zod` / `date-fns` / `glob` 都是 `type: module` 却**有** `require` 分支，
  可正常 `require`；`chalk` / `commander` 没有，行为完全不同。

### 模块 ④ 版本行为漂移（`drift`）

- **输入**：声明 range、实际安装版本、可选的历史版本 `exports` 指纹（离线包）；
- **输出**：`VERSION-BEHAVIOR-DRIFT`——"代码写的是旧版本 API，装的是新版本"；
- **确定性纪律**：只在**有离线指纹**时判定；无指纹记 `NO-BASELINE`，**不得猜测**。

### 模块 ⑤ 报告与退出码（`report`）

- **输出**：人读摘要 + `--json` 机读；
- **退出码语义**（唯一定义见 `data/README.md` §5）：`0` 无问题 / `1` 有问题 / `3` 依赖缺失或不可解析 / `4` 用法错误；
- **确定性纪律**：**"零命中"与"算不了"必须可区分**（退出码不得同值）。

## 六、边界与非目标

**不做清单**：

- ❌ 不做包发布检查（`publint` / `arethetypeswrong` 领域）；
- ❌ 不做未使用导入检测（`knip` 领域，方向相反）；
- ❌ 不做类型检查（不重复 `tsc`）；
- ❌ **不做 Python / PHP / Go / Rust**——首期只锁 Node/TS；
- ❌ 不联网解析 registry，不下载远端包；
- ❌ **不执行被测工程的任何代码**（只读文件）。

**⚠️ 与 `FixProve/fixprove` 的五条切割**（竞品实机核验记录）：

1. 它 CLI/engine MIT 但 GitHub App 与 web **闭源 proprietary**；本案**全部 MIT**；
2. 它 **TS/JS 侧实测 0 findings**（`fixprove check probe_fp.js --json` → `findings: []`，
   而文件含确定不存在的 `notARealExport`）；本案以 TS/JS 为**主战场**；
3. 它仓库 366 个文件中大量为商务/法务文档；本案**纯工具**；
4. 本案的"**同代码不同包对照组**"是独立设计（同一份 CommonJS 写法对 `chalk` 判 MISMATCH、
   对 `zod`/`glob` 判 RESOLVED）；
5. **不引用、不移植其任何代码**。

**免责**：本工具为静态分析，`AMBIGUOUS` 态表示"不可静态判定"，**不代表代码有错**。
退出码只反映本工具在该输入下的判定，**不构成代码正确性保证**。

**隐私红线**：纯本地，零上传，不采集源码内容；基准语料中的包版本指纹为公开 `package.json` 结构，不含私人代码。
产物与日志中不得出现用户绝对路径（路径一律相对化或哈希化）。

**品牌隔离**：本案与系列其他题（`10-27-versionaudit` 离线版本约束审计、`10-21-tripwire` 数据往返保真）
**文档互不提及**，代码不共享。切割点：versionaudit 判**版本约束是否成立**（semver 解析）；
本案判**已装的那一份的导出面是否认得这段调用**。

**结论纪律**：所有判定必须附**可复核证据**（具体文件 + 行号 + `exports` 字段原文行），
不得只给结论；实测数字一律标注命令与日期。
